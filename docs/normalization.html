归一化 / 归约类：Softmax · LayerNorm · RMSNorm

三个算子的共同骨架：一行一个 block，块内树形归约求统计量，最终一次写回。区别只在"归约几次、要不要减均值"。

先明确“行”：本文把输入看成 [B, N]，每个 batch 的一行长度为 N；归一化沿最后一维 N 进行，不会把不同 batch 的行混在一起。于是 grid = B，第 blockIdx.x 个 block 只负责第 blockIdx.x 行。
归约和归一化不是一回事：归约负责把一行压缩成统计量（例如 max、sum、mean）；归一化负责拿这个统计量重新访问该行并生成输出。GPU 优化的关键，是让这两步在同一个 block 内完成，减少中间结果落到显存。

一、它们为什么是一类：同一个"行归约"骨架

Softmax、LayerNorm、RMSNorm 都有一个共同特征：对矩阵的每一行做一个统计量（max / 和 / 平方和），再用这个统计量归一化该行。 问题本质是 row-wise reduction——把长度 N 的一行数据"压成一个标量"。这决定了它们的 CUDA 实现共享同一套模板：

  1. 一行一个 block（grid = B，block = 256 线程），线程只在自己的行里工作，block 之间零通信。
  2. 线程粗化（grid-stride）：每线程先串行扫 N/BLOCK 个元素（如 idx = tid; idx < N; idx += BLOCK），得到线程私有局部量。
  3. 块内树形归约：256 → 128 → 64 → 32，每层用 __syncthreads 保证可见，落后线程负责累加。
  4. warp 内 shuffle 归约：32 → 1 不用共享内存，用 __shfl_down_sync 在寄存器间传递，省掉最贵的 sync。
  5. 广播统计量 + 一次写回：所有线程拿到同一行标量，各自归一化自己的元素。
全局行数据→ 线程私有局部量→ 共享树形归约 (256→32)→ warp shuffle (32→1)→ 广播 + 归一化写回

把一行数据带着算一遍

假设一行是 x = [1, 2, 3]。三种算子都看同一行，但“统计什么、输出想表达什么”不同：

算子先得到的统计量输出含义
Softmaxmax=3，再求 Σexp(x-3)三个位置的非负权重，总和为 1，较大的输入权重更大
LayerNormmean=2，再求方差减均值、除标准差；这一行输出约为 [-1.225, 0, 1.225]
RMSNormmean(x²)=14/3只按这一行的 RMS 缩放，不把均值移到 0

这个例子也解释了为什么三者不能只看名字：Softmax 的“减 max”只是为了防止指数溢出，不是 LayerNorm 意义上的 centering（减均值）。

归约树长什么样——以一行 8 个元素为例，先求它们的 max（Softmax 第一步用的就是它）：每轮两两取大，层数减半，从 8 个值减到 1 个标量。

两两取 max ↓
7 9 8 6
再取 max ↓
9 8
↓
9

8 个元素只需 3 层就归约成一个标量（并行度每层减半）。256 个线程就是把同样的树挖深 8 层。

二、归约的两种手段（骨架核心）

块内树形归约（256 → 32）

for (int s = BLOCK/2; s >= 32; s >>= 1) {
    if (tid < s) sdata[tid] += sdata[tid + s];
    __syncthreads();
}

每轮参与线程减半：第 1 轮 128 个线程把 sdata[i+128] 累加到 sdata[i]，第 2 轮 64 个……直到只剩 32 个有效值（一个 warp 的量）。每轮之间必须 __syncthreads，否则可能读到还没写好的中间值。

warp 内 shuffle 归约（32 → 1）

for (int s = 16; s > 0; s >>= 1)
    val += __shfl_down_sync(0xffffffff, val, s);

降到 32 之后，剩下的线程恰好在一个 warp 内。warp 是 SIMD 一起执行的，__shfl_down_sync 直接从"比我低 s 位的 lane"那把值读进寄存器——不需要中间写共享内存，也不需要 __syncthreads。这就是"树形归约做到 32 为止，最后一步换 shuffle"的全部理由。

一个易错点：shuffle 的步长从 16 开始（不是 32）。因为 32 已是 warp 宽度，shfl_down(32) 会越界返回自身，导致值被翻倍。

一个 block 的完整时间线

分配行：block 通过 row = blockIdx.x 找到本行起始地址；线程 tid 处理 tid, tid+BLOCK, ... 这些位置。
局部计算：每个线程在寄存器里先算自己的局部 max、sum 或 sum-of-squares，再把一个局部值放进 shared memory。
合并局部值：shared memory 完成 256→32，最后一个 warp 用 shuffle 得到整行唯一统计量；中间的同步保证生产者和消费者顺序正确。
生成输出：统计量广播给所有线程，各线程再次按 grid-stride 遍历本行，计算最终值并写回对应位置。

为什么 block 之间不用通信？ 每个 block 只处理一行，行与行之间没有依赖；这让整个 batch 可以同时启动多个 block。代价是单行很短时线程利用率可能不高，实际库通常还会针对不同 N 选择不同 kernel。

三、逐算子原理与区别

Softmax kernels/softmax_v1.cu 0.031 ms · maxErr 1.7e-08
softmax(x)_i = exp(x_i - max) / Σ_j exp(x_j - max)

为什么减 max：直接算 exp(x_i) 会在 x_i 稍大时上溢（exp(90) 已超 fp32 范围）。减掉行最大值后指数 ≤ 0，值域稳定在 (0,1]，这是数值安全版的标准写法。

为什么是两次归约：softmax 需要两个统计量——先扫一遍求 max（第一次归约），再扫一遍求 Σ exp(x-max)（第二次归约），最后第三次写回归一化值。两次归约之间有数据依赖（求和需要先知道 max），所以是串行的两轮。

特点：纯逐元素，不引入额外可学习参数。fused 到单个 kernel，中间结果（exp 值）不再写回全局内存。

在一行上收什么（下半部分那条向量就是一整行数据）：

xxxx
maxmaxmaxmaxΣexpΣexpΣexpΣexp

先整行归约出 max（第 1 趟），再用它归约出 Σexp(x-max)（第 2 趟）——因为第 2 趟要用第 1 趟的结果，所以两趟是串行的。

LayerNorm kernels/layernorm_v1.cu 0.030 ms · maxErr 4.5e-06
y = (x - mean) · rsqrt(var + eps), mean = Σx/N, var = Σ(x-mean)²/N

为什么也是两次归约：第一次归约求 Σx 得 mean；第二次归约求 Σ(x-mean)² 得 var。后者依赖前者（方差要用均值），所以同样是串行两轮。

关键实现巧思：求方差那轮循环里，先把差值 d = x - mean 顺便暂存到输出数组 ry[idx] = d，最后一轮拿到 inv = rsqrt(var+eps) 后直接 ry[idx] *= inv——省掉一次全局显存读（不用再读一遍 x）。

与 softmax 的区别：都有两次依赖归约，但 softmax 归约的是 max 与 sum-of-exp，layernorm 归约的是 sum 与 sum-of-sq；layernorm 引入了"暂存差值"以减少写回。

在一行上收什么：

xxxx
ΣxΣxΣxΣxΣd²Σd²Σd²Σd²

先归约出 mean = Σx/N（第 1 趟），再归约 var = Σ(x-mean)²/N（第 2 趟）。第二行里其实不存 d=x-mean 的八个格子，而是算的时候顺手复用。

RMSNorm（LLaMA/Qwen 标配） kernels/rmsnorm_v1.cu 0.031 ms · maxErr 1.7e-06
y = x · rsqrt(mean(x²) + eps) · g, mean(x²) = Σx²/N

与 LayerNorm 的本质区别：去掉 centering（减均值）。公式里没有 x - mean，只剩"除以 RMS（均方根）"。

为什么更快（面试考点）：

  • 一次归约 vs 两次串行归约：只需 Σx² 一个统计量，没有 mean 的依赖链，天然少一整轮归约 + sync；
  • 不用暂存 x-mean：省一次全局显存读写（对 LayerNorm，减 mean 那个中间量要么重读要么暂存）。

为什么引入 g（gamma）：可学习缩放参数。LLM 里大模型（LLaMA、Qwen、Mistral）发现去掉 centering 只保留缩放几乎不损精度、还更快，于是 RMSNorm 成为大模型标配。g 推理时也要乘。

代码形态：与 layernorm 几乎同构，就是把"两轮归约"删成"一轮"（sum_sq = Σ rx² → 一次树形 + warp 归约 → inv = rsqrtf(s[0]/N + eps) → 写回 x · inv · g）。

在一行上收什么——只有一趟：

xxxx
Σ x² 　（没有第二趟！）

对比上面 LayerNorm 的两行、Softmax 的两行——RMSNorm 从头到尾只有一次归约：没有 mean，自然也没有 var 那趟依赖。这就是它比 LayerNorm 快、又几乎不掉精度的根源。

四、三者区别总览

算子统计量归约次数是否减均值可学习参数
Softmaxrow max、Σexp(x-max)2减 max（数值稳定，非 centering）无
LayerNormmean、var2是（本实现无 affine，工程常用 β/γ）
RMSNormmean(x²)1否g (gamma)
为什么 fused 是最大卖点：PyTorch 原生把 RMSNorm 拆成 pow→mean→rsqrt→mul 多个 kernel，中间结果反复写回显存；fused 一次加载、一次写回，3-5x 提速。这正是"手写算子 vs 库算子"在 memory-bound 问题上最典型的获胜场景（对比 GEMM 的 compute-bound，手写反而难赢）。
一句话区别：Softmax 是"概率归一化"（两次归约：max + sum-of-exp），LayerNorm 是"减均值除标准差"（两次归约：mean + var），RMSNorm 是"只除 RMS 不减均值"（一次归约）——归约次数从 2 降到 1，是 RMSNorm 比 LayerNorm 快的根本原因。
