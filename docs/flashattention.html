FlashAttention：分块 + Online Softmax

四个版本复现 FA2：v1 分块 + online softmax → v2 causal → v3 warp-per-row → v4 fp16 Tensor Core。核心主张始终是「让 S 矩阵永不落地 HBM」。

一、先看标准 attention 哪里"贵"

给定 Q/K/V ∈ RN×D，单头标准 attention 是两步矩阵乘夹一个 softmax：

S = Q · Kᵀ / √D (N×N 的分数矩阵，O(N²D) 次运算，O(N²) 内存) P = softmax(S) (按行归一化) O = P · V (N×D 输出)

朴素实现的瓶颈：S 矩阵大小是 N×N，对长序列（N=8192）是 8192²×4B ≈ 256MB。必须把 S 写回全局内存（HBM）再读回来做 softmax 和 ×V——这一写一读完全受 HBM 带宽限制，是 memory-bound 的灾难。

二、核心思想：分块 + Online Softmax

FlashAttention 的洞见有两点：

  1. 分块（tiling）：把 K/V 切成 Bc 行一块，每次只算 S 的一小条 Br×Bc，在片上算完 softmax 和 ≤×V 的贡献，S 块用后即弃——永远不落 HBM。
  2. Online Softmax：softmax 的 max 和 sum 可以"流式"维护，不用等所有分数算齐。每来一个新块，旧统计量用一个系数 alpha 修正即可。

Online Softmax 的数学（关键）

对每一行，维护三个运行量：m（迄今最大分数）、l（Σexp(S-m)）、acc（Σexp(S-m)·V，未归一化分子）。每处理一个新块，新旧两块合并：

m_new = max(m_old, m_row) // m_row 是本块最大分数 alpha = exp(m_old - m_new) // 旧最大变小 → 旧统计要按比例缩小 l_new = alpha·l_old + Σ_c exp(S[c]-m_new) acc = alpha·acc + Σ_c exp(S[c]-m_new)·V[c]

直觉：旧的最大值若被新块超过，旧块的 exp(S-m_old) 全部偏大，乘 alpha 统一缩回去，再叠上新块的贡献。最终 O = acc / l。这就是"不必回头、单遍扫过 KV"的全部依据。

Q 行(驻寄存器)→ 逐块搬 K/V 进 smem→ 算 S 块 + online softmax→ 累加 O(=acc/l)→ 写回

三、逐版原理

v1 · 分块 + Online Softmax kernels/flashattention_v1.cu 0.199 ms · N=512, D=64, Br/Bc=32

线程映射：一线程一行。每 block 处理 Br=32 行 Q、block 内 32 线程各管一行，逐块搬 Bc=32 行 K/V 进 smem，内层循环扫完所有 KV 块。

关键结构：Q 行全程驻在寄存器 q_reg[D]（外层循环复用，不回 HBM）；每轮把 S[Bc] 这一小条分数在寄存器里算完、做完 online softmax、累进 acc[D]——S 从不写回全局内存。

这版的价值：验证了 online softmax 的数值正确性（maxErr 2.4e-07 与标准实现一致），并建立了分块骨架。问题也同时埋下：一线程一行导致每个 block 只有 1 个 warp，occupancy 极低（见 v3）。

v2 · Causal Mask（模板双模式） kernels/flashattention_v2.cu full 9.43 / causal 4.71 ms · N=8192 · causal 2.00x

加了什么：GPT 自回归的 causal mask——第 q 行只能看到 j≤q 的 KV（下三角）。用 template<bool IS_CAUSAL> 做编译期双模式，运行时 bool 在包装层 if/else 派发，kernel 内无运行时分支。

// 块级截断：整块跳过未来信息
const int kv_end = IS_CAUSAL ? (q_row_max / Bc + 1) : num_kv_blks;
for (int kv_blk = 0; kv_blk < kv_end; ++kv_blk) {
    ...
    if (IS_CAUSAL && kv_col > q_row) { S[c] = -1e20f; continue; }  // 对角线块逐元素 mask

两层式因果：① 循环上界按 block 粒度截断（必须全 block 一致，否则 __syncthreads 被最慢线程拖着走，省不了块）；② 对角线块内再逐元素 mask。causal 理论上省一半计算（只算下三角），N=8192 时实测 2.00x ——恰好命中理论上限。

踩坑：初版在 N=512 时 causal 反而 0.84x（负优化）。ncu 定位：occupancy 仅 2.08%，每 block 只 1 个 warp，内存延迟完全无法隐藏，省下的计算被串行延迟淹没。教训：低 occupancy 下谈计算量优化是空中楼阁。
v3 · Warp-per-row（FA2 的核心重划分） kernels/flashattention_v3.cu full 17.7 / causal 8.8 ms · N=8192 · causal 2.01x

解决什么：v2 一线程一行的架构，每线程要同时持有 q_reg[64] + acc[64]，寄存器爆炸 → 每 block 只能 1 warp → occupancy 2%。

改法（对齐 FA2 思想）：一 warp 一行。block = 256 线程 = 8 warps，每 warp 独占一行 Q，warp 内 32 个 lane 分摊 D=64 维（每 lane 只存 q_reg[2] + acc[2]）。寄存器需求从 ~130 降到 ~40/线程，occupancy 2% → 79%。

// 每个 lane 只负责 DQ=D/32=2 维
__shared__ float Ktile[Bc][D+1];   // 【padding】行宽 65 与 32 互质
__shared__ float Vtile[Bc][D+1];
// 每 lane 独立算自己那行 K 的完整点积（Bc==WARP，c=lane 正好一个分数）

三个踩坑（教训）：

  • 发散分支禁用跨 lane shuffle：初版在 causal 分支下用 __shfl_xor 归约 → 直接死锁。解法：每 lane 独立算完整点积，不再跨 lane 凑。
  • 不能 return 提前退出：if(q_row>=N) return 会让部分 warp 退出、留下 __syncthreads 死等。改 valid 标记"陪跑"。
  • 列访问 bank conflict：K/V 按列访问时地址步长 = D。D=64 是 32 的倍数 → 全撞同一 bank（9.4 亿次冲突）。修法 Ktile[Bc][D+1]，步长 65 与 32 互质，冲突降 14x。

仍比 v2 慢 1.8x 的归因：K/V 随 block 数增多重复搬运 + Q 点积冗余。说明 occupancy 与算术强度是三角债，拉满一个可能拖累另一个。

v4 · fp16 + 手写 Tensor Core（复现 FA2 的关键一步） kernels/flashattention_v4.cu N=4096 1.53 ms（full attention）

解决什么：v3 是 fp32，QKᵀ 和 PV 两个矩阵乘仍是 FMA 逐点算。与 GEMM v4 同理——真正复现 FA2 性能要把这两个 GEMM 换成 Tensor Core。

改法：Q/K/V 用 fp16，累加和 softmax 用 fp32。S = Q@Kᵀ 和 O += P@V 都用 mma.sync.m16n8k16。

  • warp 划分对齐 FA2：每 block 处理 Bq=64 行 Q，4 个 warp，每 warp 独占 16 行（正好一个 mma 的 M-tile）。
  • 行归约全在 warp 内：每 warp 扫全部 K/V 块，softmax 的 max/sum 归约不跨 warp 通信，直接继承 v3 的在线软 max。
  • fragment 布局复用 gemm_v4 的已验证版：load_A_verified 直接搬 gemm_v4 的 A fragment 布局（a0~a3），踩过的坑不再重踩。

当前边界：Stage 1 只做 full attention（非 causal），Bq=Bc=D=64 固定，N 需被 64 整除——纯最小实现，先验证 mma 通路与布局正确，与 GEMM v4 定位一致。

四、四版区别总览

版本线程映射精度causal核心增量
v1一线程一行fp32否分块 + online softmax（S 不落 HBM）
v2一线程一行fp32✔ 模板双模式causal 块级截断 + 逐元素 mask

一句话主线：v1 奠定"分块 + online softmax"的正确性骨架；v2 补 causal 并踩出 occupancy 的教训；v3 用 warp-per-row 把 occupancy 从 2% 拉回 79%；v4 最终把两个 GEMM 换成 Tensor Core——四步走完，手工实现正式向 FA2 对齐。
