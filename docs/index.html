GEMM

主线：分块复用 + 访存优化，把「每线程算一个 C」逐步升级成「每 warp 用 Tensor Core 算 16×8×16」。

覆盖：gemm_v0 朴素 → v1 smem tiling → v2 ldg 只读缓存 → v3 CUTLASS → v4 手写 mma.sync

三类算子的共同地基

虽然表面各异，三类算子反复用到同一批 CUDA 基本功，读任意一类前先看懂这几件：

概念一句话三类里的现身
Shared Memory 分块 把全局内存里会重复读的数据先搬进片上 SRAM 复用，换取更少的 HBM 访问。 GEMM 的 As/Bs tile；FA 的 Ktile/Vtile；Norm 的 s[BLOCK]
Coalesced（合并访存） 同一 warp 的 32 个线程在相邻地址读写，合并成一次 128B 事务。 GEMM 搬 tile 的 tid, tid+256… 接力；FA/Norm 搬行数据
Bank Conflict shared memory 按 32 路 bank 组织，步长为 32 倍数的列访问会全撞同一 bank。 GEMM v1 的列优先反例；FA v3 的 Ktile[Bc][D+1] padding
Warp 内归约 __shfl_down_sync 在寄存器间搬数，避免 __syncthreads 开销。 Softmax/LayerNorm/RMSNorm 的 32→1 归约；FA 的 max/sum
Occupancy 与延迟隐藏 SM 上并发 warp 越多，越能用计算掩盖内存延迟。 FA v3 的核心教训：occupancy 2%→79% 比一切计算优化都重要
